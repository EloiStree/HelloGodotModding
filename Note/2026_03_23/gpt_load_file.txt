

# 🧠 Core Idea: Godot Doesn’t Have “Mods” — You Fake It

Godot doesn’t ship with a Steam Workshop-style mod system. What you do instead:

* Load external files (scripts, scenes, data)
* Execute or attach them at runtime
* Pray users don’t write cursed code

---

# ⚙️ Method 1: Load External GDScript at Runtime

Yes, you *can* load `.gd` files dynamically.

### Example:

```gdscript
var script = load("user://mods/my_mod.gd")

if script:
    var instance = script.new()
    add_child(instance)
```

### Key points:

* `user://` is your sandboxed writable folder (safe-ish place for mods)
* Mods are just `.gd` scripts dropped there
* You instantiate them like normal scripts

### Problem:

* No sandboxing → mods can access your whole game
* Players can break everything (or cheat, or worse)

---

# 🧱 Method 2: Use Packed Scenes (`.tscn`) for Mods

This is cleaner and less chaotic.

### Example:

```gdscript
var scene = load("user://mods/mod_scene.tscn")

if scene:
    var instance = scene.instantiate()
    add_child(instance)
```

### Why this is better:

* Mods are structured (nodes, signals, etc.)
* Less likely to explode than raw scripts
* Easier for modders to understand

---

# 📦 Method 3: Define a Mod API (Recommended)

If you don’t do this, your future self will hate you.

Instead of letting mods do *anything*, you:

### 1. Create a base class

```gdscript
# mod_base.gd
class_name ModBase

func on_load(game):
    pass
```

### 2. Load mods and call controlled hooks

```gdscript
var script = load(path)
var mod = script.new()

if mod is ModBase:
    mod.on_load(self)
```

### Benefits:

* You control what mods can touch
* You can version your API
* You reduce chaos from “random script executes everything”

---

# 🔐 Method 4: Sandboxing (Spoiler: Not Really Possible)

GDScript:

* Has no real sandboxing
* Mods can call anything your game can

If you *really* care about safety:

* Don’t allow raw scripts
* Use:

  * JSON configs
  * Custom scripting language
  * Limited command system

---

# 🧩 Method 5: Data-Driven Modding (Safer)

Instead of code, let players modify data:

* JSON / CSV files
* Custom config files

Example:

```json
{
  "enemy_speed": 300,
  "health": 200
}
```

Then load it:

```gdscript
var data = JSON.parse_string(file.get_as_text())
```

### Result:

* Much safer
* Less flexible
* Less likely to summon undefined behavior demons

# 💥 Reality Check

Letting users run GDScript at runtime means:

| Risk             | Outcome |
| ---------------- | ------- |
| Bad code         | crashes |
| Infinite loops   | freezes |
| Malicious code   | …yeah   |
| Version mismatch | chaos   |

If you’re shipping commercially, don’t expose raw scripting unless you trust your players more than most developers do.

---

# 🧠 Smarter Hybrid Approach

What actually works well:

* Use `.tscn` + limited scripts
* Provide a clean API (signals, hooks)
* Load from `user://mods`
* Validate mods before loading

---

# 🧪 Minimal Mod Loader Example

```gdscript
func load_mods():
    var dir = DirAccess.open("user://mods")
    if dir:
        dir.list_dir_begin()
        var file = dir.get_next()
        
        while file != "":
            if file.ends_with(".gd"):
                var script = load("user://mods/" + file)
                var mod = script.new()
                add_child(mod)
            file = dir.get_next()
```
